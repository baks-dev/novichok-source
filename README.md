# НОВИЧОК · Первые 90 дней

Рабочий локальный прототип для руководителя склада, магазина, продаж или офиса: услышать трудность новичка и довести помощь до результата. Все люди вымышлены.

## Запуск

Требуется **Node.js 24+** (используется встроенный `node:sqlite`). Сторонних зависимостей нет.

```sh
npm start
```

Открыть http://127.0.0.1:3000 . Приложение не требует сборки, npm install и внешней сети. Порт: `PORT=3001 npm start`. По умолчанию сервер доступен только с локального компьютера. Для локальной демонстрации отдельным процессом: `npm run demo`; PID в `data/server.pid`, лог в `data/server.log`. Остановить этот процесс: `kill <PID из файла>`.

## Что попробовать за две минуты

1. В режиме руководителя открыть Алексея Миронова: нет личного доступа к терминалу склада, помощь просрочена.
2. Создать конкретный шаг помощи, указать ответственного и срок.
3. В существующей договорённости нажать «Зафиксировать результат». Без результата её нельзя закрыть. Сигнал новичка остаётся.
4. Перейти к ответу новичка, отметить настроение и три ответа, отправить.
5. Вернуться к руководителю: приоритет и история обновились. Если все препятствия сняты и нет просроченной помощи, статус — «Без сигналов».
6. «Копировать для Битрикс24» копирует контекст для **ручного** переноса. Это не интеграция.

На текущем локальном демостенде шаги для Алексея уже выполнены при браузерной проверке. В чистом архиве база не включена: при первом запуске появятся исходные восемь сотрудников.

## Правила очереди

- **Нужна помощь:** в последнем ответе нет инструментов, понимания задач или поддержки; настроение «сложно»; либо есть просроченная помощь.
- **Связаться:** нет первого ответа, прошло 7 дней без обратной связи, либо настроение нейтральное.
- **Без сигналов:** в последнем ответе нет препятствий и нет просроченной помощи. Это не прогноз удержания.
- В очереди сотрудники с 1-го по 90-й день включительно. История остаётся в базе после 90-го дня, но интерфейс архива не реализован.

## Хранение и ограничения

SQLite: `data/novichok.sqlite`, создаётся автоматически, даты синтетических событий отсчитываются от первого запуска. Изменения сохраняются после перезапуска. Одна SQL-операция на изменение; первоначальное заполнение — транзакция. Временные метки в UTC, отображение времени — часовой пояс браузера; рабочий день и границы сроков считаются по UTC (для промышленного внедрения нужен корпоративный часовой пояс).

**Это общий деморежим без авторизации и разграничения прав. Не размещайте публично с реальными персональными данными.** Выбор новичка в форме — демонстрация роли, не защищённый личный кабинет. Нет уведомлений, автоматических приглашений, импорта из Битрикс24 и обещаний снизить текучесть. Комментарии видны руководителю, форма явно не анонимна. Нужны правила доступа, согласования обработки данных и хранения перед пилотом.

## Проверки

```sh
npm test
```

`tests/app.test.js`: API, приоритеты, валидация, запрет повторного закрытия, сохранение истории и SQLite после перезапуска, доступ к статике. Браузер вручную: создание помощи, закрытие с результатом, новый ответ, изменение статуса; поиск/фильтр и мобильная ширина проверяются отдельно. Запись `artifacts/demo.mp4` — без звука, менее 3 минут. Код записи `scripts/record-demo.js` использует локальный Chrome CDP и ffmpeg и не нужен для запуска приложения.

## Состав

- `PRODUCT.md` — задача, границы, критерии приёмки.

- `tests/` — автоматические проверки через `node:test`.
